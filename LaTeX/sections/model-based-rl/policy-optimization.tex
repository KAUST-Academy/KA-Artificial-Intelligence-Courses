\begin{frame}{Model-Based Policy Optimization}
\begin{itemize}
    \item We can also use model-based RL for policy optimization
    \item Key Idea:
    \begin{itemize}
        \item Augment data with model-simulated roll-outs
    \end{itemize}
    \item Algorithm (\textbf{MBPO}; Janner et al., 2019):
    \begin{enumerate}
        \item Collect data using current policy $\pi_\theta$, add to $D_{\text{env}}$
        \item Update model $p_\phi(s' \mid s, a)$ using $D_{\text{env}}$
        \item Collect synthetic roll-outs using $\pi_\theta$ in model $p_\phi$ from states in $D_{\text{env}}$;
              add to $D_{\text{model}}$
        \item Update policy $\pi_\theta$ (and critic $Q$) using $D_{\text{model}}$
        \item Go to step 1
    \end{enumerate}
\end{itemize}
\end{frame}

\begin{frame}{Model-Based Policy Optimization}
\begin{itemize}
    \item We can also use model-based RL for policy optimization
    \item Key Idea:
    \begin{itemize}
        \item Augment data with model-simulated roll-outs
    \end{itemize}
    \item Algorithm (\textbf{MBPO}; Janner et al., 2019):
    \begin{enumerate}
        \item Collect data using current policy $\pi_\theta$, add to $D_{\text{env}}$
        \item Update model $p_\phi(s' \mid s, a)$ using $D_{\text{env}}$
        \item Collect synthetic roll-outs using $\pi_\theta$ in model $p_\phi$ from states in $D_{\text{env}}$;
              add to $D_{\text{model}}$
        \item Update policy $\pi_\theta$ (and critic $Q$) using $D_{\text{model}}$
        \item Go to step 1
    \end{enumerate}
    \item Compatible with variety of model-free RL methods
    \item MBPO's design: \emph{short, branched} roll-outs from \emph{real} states
          keep model error from compounding
\end{itemize}
\end{frame}

\begin{frame}{But We Go Back to the Env Anyway --- Why Bother?}
\begin{itemize}
    \item Fair question: step 1 still collects real data. So why not skip the
          model and just take \emph{more gradient steps} on the real replay
          buffer? Those are free too
    \item Because the buffer only holds actions the \emph{old} policy took
    \item A changing $\pi_\theta$ needs $Q(s,a)$ at the \emph{new} actions
          $a \sim \pi_\theta$ --- and there is no data there. The critic must
          extrapolate (we will name this failure in Part 2)
\end{itemize}
\end{frame}

\begin{itemize}
    \item Fair question: step 1 still collects real data. So why not skip the

          buffer? Those are free too
    \item Because the buffer only holds actions the \emph{old} policy took

          $a \sim \pi_\theta$ --- and there is no data there. The critic must
          extrapolate (we will name this failure in Part 2)
    \item A buffer can only be \textbf{replayed}. A model can be
          \textbf{queried}: hand it $(s, a_{\text{new}})$, it hands back
          $(r, s')$
\end{itemize}
\vspace{0.2em}
\begin{center}
\emph{The model answers counterfactuals --- ``what if I had done \emph{this}
instead?'' --- which logged data cannot.}
\end{center}
\begin{itemize}
    \item The env visit is only to keep the model honest \emph{where the policy
          now goes}; the model does the rest
\end{itemize}
\end{frame}
